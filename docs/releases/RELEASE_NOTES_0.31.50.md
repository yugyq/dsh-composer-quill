# 0.31.50

只改 README，没有代码改动。版本号抬上来是为了让 npm 包里带上新版说明。

## 为什么改

看了三个同类项目的首页——zsh-autosuggestions、starship、atuin——开场结构是同一个公式：

1. 一句标语（≤12 字，常用类比）
2. 一句字面说明「它到底做什么」
3. 首屏就有图
4. 关键词加粗 + 短句的功能清单
5. 安装命令在前三分之一

**没有一个是靠段落讲「什么时候你会需要它」。** 之前那版正好反过来：开头三段散文讲场景，功能清单埋在下面。

## 现在长什么样

```
# 续笔 · dsh-composer-quill

输入框里的自动建议——补的不是命令，是你接下来要说的话。

回合结束时它给几条「下一句」；你打字停一下，它把后半句接上。
Tab 采用，Esc 忽略，从不发送。

[截图]

dsh plugin --profile desktop add dsh-composer-quill

- 不知道怎么开口：回合结束先摆几条下一句，挑一条改比对着空白想快
- 句子组不顺：写个开头，后半句接上；整句都乱，它给一整段整理过的
- 说到一半被打断：切走再回来，建议还在原位
- 每次都要重打的那段话：从你自己的历史里取，不花模型调用
```

## 通篇统一了什么

| 节 | 之前 | 现在 |
|---|---|---|
| 四种建议 | 四级标题 + 段落 | `**关键词**：一句话` 四行，开头先说「三种花模型调用，历史不花」 |
| 按键 | 一段分号串 | 表格 |
| 设置 | 混合 | 表格 + 三条加粗说明 |
| 隐私 / 它怎么工作 / 还没做好的地方 / 诊断 | 段落 | 加粗关键词的列表 |

分隔符统一成全角冒号（原先 `** —— ` 与 `**：` 两种混用）；`它怎么工作` 里的路由从三个补成四个，因为新增了 `/usage`。

从源码接入、判断在跑哪一版这类开发者细节移进 [DEVELOPMENT](https://github.com/yugyq/dsh-composer-quill/blob/main/docs/DEVELOPMENT.md)，README 只留一行指路。
