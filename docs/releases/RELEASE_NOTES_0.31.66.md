# 0.31.66 — 压制的门槛降到两条

0.31.61 起，连着忽略三条建议就只留句尾补全、整段改写暂停。上线后翻了 24 小时的真实日志，`ignoredStreak` 到过 1 的有 32 次、到过 2 的有 6 次、到过 3 的一次也没有，`suppressRewrites` 从头到尾是 `false`。

门槛定在三条，等于这条规则从来没生效过。这一版改成两条。

## 改了什么

- `client.js:49` `IGNORE_STREAK_LIMIT = 3` → `2`。
- 设置里那一行文案跟着改：「忽略两次后暂停整段改写」/ “Pause rewrites after two ignores”。
- S50 场景改成两次忽略：第一次仍画改写，第二次之后第三条请求照发但不画，尾巴补全照常，采纳一次即恢复。

## 场景里的一个真实行为

S50 首跑是红的，原因不是阈值：忽略那一刻如果还有请求在飞，它是按旧计数发起的，回来时仍然会画。这是对的，但会让断言读到上一次的结果。现在打第三个字之前先等 `suppressState().on === true` 再走。

反证：把阈值改回 3 并重建 bundle，S50 变红（`压制态={'on': False, 'streak': 2, 'allow': True}`），65/66；改回 2 恢复 66/66。

## 一个容易踩的坑

`dev/harness/src.js` 是 `await import('../../client.js')`，esbuild 会把 `client.js` 内联进 `dev/harness/bundle.js`。改完 `client.js` 必须重跑 `node dev/harness/build.mjs`，否则场景跑的还是旧插件——做阈值反证时就因此看到过一次假的 PASS，查了两轮才定位。

## 验证

- 单测 149 项全过。
- 浏览器场景 66/66。
- `npm pack` 24 个文件。

## 说明

同一份日志里 165 条 `stream-end` 全是我自己的压测流量，真实 compose 调用是 0 次。所以这次改动只有「三条从没碰到过」这一个证据，样本还小；等有真实用法，再看两条是不是也偏保守。

装上后需要重启桌面应用（`index.js` 未变，`Ctrl+R` 只重载浏览器端，足够让这一版生效）。
