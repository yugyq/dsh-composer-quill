# 0.33.2 — 换会话之后，上一句不该跟过来

issue #10 报的是「`Ctrl+N` 之后旧会话的补全仍画在新输入框里」。它在 0.33.0 与 0.31.64 都能复现，而我们的 66 条场景一直是绿的。这一版把根因拆开：不是一个 bug，是四处各自都「看起来没问题」的缺口，加上一条让它们一起失声的优先级。

## 四处行为变化

| 变化 | 改之前 | 改之后 |
| --- | --- | --- |
| 迟到的流帧 | 帧落进「当时 store 自称的那个会话」 | 每帧带上它被请求时的会话，对不上就丢弃 |
| 图层的宿主 | 节点被移除后，下一次 `render()` 认为「没挂载」并重新挂到**当时屏幕上的编辑器** | 已被移除就只清空，不再重挂 |
| 下一句候选 | 只判断「空输入框 + 有候选」，不看候选属于谁 | 候选的会话必须等于当前会话，灰字与「按 Tab 采纳」共用这一条 |
| 存档的优先级 | 本地存过的建议优先于宿主刚说的「没有」 | 宿主说没有就记下「没有」，存档不许压过它；存档还带 `BUILD`，跨版本一律不认 |

## 四处怎么发现的

**迟到的帧**：`client/store.js` 的五个流式 handler 都写「当前快照」，`streamStart` 拿到 `sessionId` 却没留给后续帧。三个条件凑齐才漏：A 的流还在路上 → 切到 B → **B 自己先发请求**（store 自称 B）→ A 的下一帧变成 B 的建议。现在每帧携带 `fromSession`，`belongs()` 对不上就丢，并计入 `droppedFrames`。

**图层的宿主**：真机日志里抓到同一刻的两条——`paint sessionId=4065c5 mounted=false` 与 `dock sessionId=883c40`。旧 dock 的图层节点已被移除，`render()` 走「节点不在就 `mount()`」，而 `mount()` 取的是当时屏幕上那个编辑器。现在「被移除」和「从没挂过」分开：前者只清空。

**候选的归属**：`nextActive` 原来有 `nextEnabled && !running && draftEmpty && kind==='next' && current!==''`，唯独没有 `state.sessionId === sessionId`（`composeActive` 有）。store 比会话活得久，于是一个空的新会话让其余条件全真。现在抽成纯函数 `nextVisible()`，11 个分支有用例。

**存档的优先级**：宿主对空会话的回答是 `result {kind:'next', count:0, reason:'empty-thread'}`，客户端却在每个挂载上 `hydrated … next` → 画出 22 字。因为这个会话从没成功问过下一句，那条「没有」没被记住，而 localStorage 里的旧台词一直在。现在「没有」会写一条 `none` 标记，存档读之前先问它；存档同时记 `BUILD`，上一版写下的建议这一版不认。

## 为什么以前的测试全是绿的

假宿主即时应答，切换时**没有在飞的帧**（原报告里也写了同样的观察）；`empty-thread` 与存储的优先级没人测过；图层重挂需要「节点被移除但实例还活着」这个组合；跨版本存档要跨一次升级才会出现。所以这版加的不是一条场景，是四条各自能变红的钉子：S55（图层）、迟到帧、候选归属、跨版本存档——把规则改回去，对应用例立刻失败。

## 顺带：重载之后不再失明

`Ctrl+R` 会把页面文档重新要一遍，注入的 `__DSH_COMPOSER_QUILL_TOKEN__` 不一定跟着回来。少了它 `/beacon` 全部被拒，`/predict` 却因同源判定照常工作——表面上一切正常，日志里从重载那一刻起一条客户端事件都没有（这次调查里 300 多条宿主事件、零条 `beacon` 就是这么来的）。现在拿到过的令牌在 `sessionStorage` 里留一份，页面再被服务一次时读回来。

## 验证

`npm test` 181 → **187**，浏览器场景 66 → **67**，`check:client` 一致。每一处都做过变异反证：`belongs` 恒真、图层规则改回旧写法、删掉会话比对、存档优先于「没有」、去掉版本比对、去掉令牌回读——各自只打红对应那条。

## 兼容与升级

- 只改了客户端。升级后 `Ctrl+R` 即生效，不必重启桌面应用。
- 存档格式新增 `build` 字段；没有这个字段的旧记录会被忽略并重新问一次模型（建议本来就是缓存，代价是多一次请求）。
- `docs/PROTOCOL.md` 与 `docs/DEVELOPMENT.md` 的事件字段没变；`README` 的计数改为 187/67。
