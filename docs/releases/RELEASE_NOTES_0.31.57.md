# 0.31.57

两轮整体审计的结果：十三项修复，全部有测试守着。

## 安全

**不带 token 的请求现在按 socket 判定。** 之前那条回退路径只校验 `Host`、`sec-fetch-site` 和自定义头——三样都是调用方自己写的，任何本机进程、任何能访问到端口的页面都能构造。`predict` 和 `beacon` 走的就是这条路。

现在要求 `req.socket.remoteAddress` 是环回地址；头只用来收窄一个已经在本机的请求；没有 socket 直接拒绝。token 路径不变，仍然可以从任何地方用。

## 数据完整性

- **四个状态文件统一目录。** 账本曾经落在家目录、日志落在 `~/.dsh`：`usageLedgerPath()` 在 `apply()` 同步段就缓存了路径，那时 `DSH_HOME` 还没设。现在共用一个解析器，环境变了会重算，并把账本一起搬过去——（本节原写「家目录里那 364 次调用会被搬进来」——这句是错的，见 0.31.58：两个进程会互相覆盖，那台机器的 364 次记录因此丢失）。
- **并发 flush 不再互踩。** 临时文件名只带 pid，防抖写入和「重置账本」撞在一起时，输的那次 rename 可能落下半个 JSON。
- **损坏的账本先改名备份**，而不是直接用零覆盖。

## 建议的正确性

- **缓存键带生效路由。** 键里原本是「会话的模型」，而实际调用优先用设置里选的模型和思考强度：切换后两分钟内会回放上一个模型的答案，思考强度则从来没进过键。
- **空结果不再钉两分钟。** `next` 拿到 0 条候选时用默认 TTL，「重试」按钮会一直读同一条空缓存，而模型早就恢复了。现在走 10 秒的否定 TTL。
- **切会话会取消上一个会话的请求。** 命中存储建议时直接 `return`，跳过了 `dismissAll()`：旧 SSE 流和防抖定时器继续跑，结果可能落进刚切过去的会话。

## 诊断

`empty-reply` 记的是实际发出的输出上限，不再是该模式的基础值（思考档位会把上限放大到 4 倍，两者不同）。

## 测试与 CI

- **三条用例从来没执行过。** `check()` 收到 async 回调时不 await 就记 ok，其中一条是 `/models` 的唯一覆盖，而且它调用了根本不存在的辅助函数。三条改成 `checkAsync`，并给 `check()` 加了护栏。
- **CI 开始跑浏览器场景。** 之前只跑单测，而两份 README 都写「跑在 CI 里」。新 job 会重建模拟器 bundle、装 Chromium、跑 55 条场景。
- **`DSH_SCENARIO_LIMIT` 不再骗人**：部分运行且已有失败时退出 1；套件还会断言实际跑满 55 条。

## 文档与打包

- 路由数三个说法（三/四/五）统一成五条；「草稿不遮蔽」改成事实（草稿会遮蔽，带遮蔽标记的改写会被丢弃）；「两个本地文件」改成三个。
- `package.json` 不再把整份 `docs/` 打进包——里面有过时的计划文档，有一份写着「全仓库没有 undo」，而撤销早就发了。现在 24 个文件，含 SECURITY.md 与 CHANGELOG.md。
- README 不再说「各花一次调用」：实测 compose 平均 1.13 次，`next` 有 15% 会补问第二次。
