# 0.33.8 — 让它用满那份本来就被允许的上下文

这一版只动宿主：模型看到的对话变长了，而多出来的部分不是新增预算，是**原本写着却没被用上**的那部分。

## 行为变化

| 变化 | 之前 | 现在 |
| --- | --- | --- |
| transcript 上限 | 1600 字符 | **3200**（短草稿 1200 → 2400） |
| 单条消息上限 | 800 字符 | **2200** |
| 行数上限 | 8 / 8 / 8 行 | 120（短）/ 200（主）/ 200（下一句），只挡病态事件数 |
| 兜底转录 | 1800 字符 | 9000 |
| `DSH_QUILL_CONTEXT` | `tight` / `full` 两档 | 删除，`full` 成为默认 |
| 成本 | — | 每次多约 580 输入 token（flash 未命中约 ¥0.0003，命中前缀缓存约 1/50） |

## 真正卡住的不是字符，是行数

`CONTEXT_BUDGET` 一直是「行数 ≤ N **且** 字符 ≤ M」同时生效。短消息组成的对话里，8 行只装进 **607 字**——而预算写着 1600 字。

```
8 行 × 平均 76 字 ≈ 607 字  ← 旧默认，两轮前的事实就没了
32 行 ≈ 1345 字             ← 仍然只装 16 轮，第 6 轮的事实进不去
200 行 ≈ 3200 字            ← 由字符数决定装多少
```

所以 0.33.8 把行数放宽到「不会先咬住」的位置，让字符预算做决定；行数只保留防病态事件流的作用。

## 实测（真模型，flash、关思考、`reasoning_effort: none`）

| 场景 | 旧预算 | 新预算 |
| --- | --- | --- |
| 事实在 10 轮前，问它是什么 | 提示词 603 字，命中 **0/4**，944ms | 1599 字，命中 **4/4**，555ms |
| 结论写在 2000 字长消息的末尾 | 单条砍到 800 字，命中 **0/4** | 2200 字，命中 **4/4** |
| 40 轮对话，事实在第 6 轮 | 提示词 794 字符，**不含**该编号，模型编出「字段 40」，0/3 | 提示词 3763 字符，**含**，编造 0/3 → 正确 **3/3** |

应用内复核（真实宿主、`POST /composer-quill/predict`）：把仓编号写在一条消息里、后面垫约 2000 字，再问「那个编号是」——

```
那个编号是            → 那个编号是 KX-9F21.        （输入 5373 token，cacheRead 512）
我们项目的仓编号是    → 我们项目的仓编号是KX-9F21 吗… （输入 5375 token，cacheRead 5632）
```

该编号距转录末尾约 2100 字符：旧 1600 预算够不着，新 3200 覆盖到。

## 为什么以前没发现

旧用例只断言「提示词里有编号」，而夹具里的对话又短又整齐，8 行足够——测试从没让「行数先于字符数触顶」这种情况发生。新增的单测 `the row ceiling never starves the character budget` 直接构造这个形状：宽窗口必须留下 `KX-7731`、窄窗口必须丢掉它、默认值必须与宽窗口一致。把行数上限改回 32 → 该条立刻红。

另一条 `a forty-turn conversation still reaches back to turn six` 用 40 轮把事实推到 32 行之外，32 行时提示词只有 1345 字、不含编号 → 红。

## 升级

`index.js` 变了：**重启桌面应用**才会生效（`Ctrl+R` 只重载浏览器端）。重启后可以在设置面板的「消耗」里看到每次补写的输入 token 明显变大——那就是预算用上了。
