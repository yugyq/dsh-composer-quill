# 0.33.10 — 底板挪下去 4 像素

0.33.9 给长建议加了白底面板，位置算错了一点：它压进了用户最后一行字的下沿。

## 行为变化

| | 0.33.9 | 0.33.10 |
| --- | --- | --- |
| 面板顶边 | 「行盒顶 + 行高 − 6」 | 「第一行字形下沿 + 2」 |
| 与用户那一行的重叠 | **4 px** | **0 px** |

## 为什么错

行盒（line box）比字形高。`line-height: 22px` 而字形只有 ~17px，多出来的空白分在上下两侧——降部（`，` `。` `g` `y` 的下半截）就住在这几像素里。

按「行盒顶 + 行高 − 6」放面板，等于在行盒底部再往上收 6px，正好切掉降部。肉眼看像「字号被裁了一点」，实际是白底盖上来。

## 现在的算法

```
const glyphBottom = Math.round(leading + glyphHeight)   // 第一行字形的下沿
top    = lineTop + glyphBottom + 2
height = scrollHeight - glyphBottom - 2 + 10
```

面板从字形下沿再往下 2px 开始，第一行（往往就是用户自己打的那行）永远完整可见。

## 验证

夹具里量的是「面板矩形」与「用户最后一个文本节点最后 8 个字符的矩形」的纵向交集：

```
0.33.9（旧写法）  panel.top=100  typed.bottom=104  coverY=4
0.33.10（新写法） panel.top=106  typed.bottom=104  coverY=0
```

- `npm test`：197 passed
- 场景：76 / 76，S64 现在断言 `coverY == 0`，描述串里直接打「压住=Npx」
- 把面板顶边改回旧写法，探针立刻读到 `coverY=4`，S64 变红
