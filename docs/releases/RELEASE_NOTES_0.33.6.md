# 0.33.6 — 拼错的标记，也不算正文

起因是一张截图：草稿是「但是」，输入框里跟着两行灰字——

```
RERITE:
但是我还是想先确认一下这个方案。
```

那个 `RERITE:` 不是用户打的，也不是模型想说的内容。

## 一处行为变化

| 变化 | 改之前 | 改之后 |
| --- | --- | --- |
| 首行的大写词 | 只认字面 `REWRITE:`；拼错就当正文 | 与 `REWRITE` 编辑距离 ≤2 即认作标记并剥掉；`SKIP`/`NOOP` 距离 ≤1 视为「没东西可补」；其他大写词仍是正文 |

## 为什么以前没拦住

提示词要求模型在「整段改写」时以 `REWRITE:` 开头，解析器用的是严格正则 `/^\s*rewrite\s*:\s*/i`。温度 1.0 下模型少打了一个 W，正则不匹配，于是这条回复退出改写分支，落进「尾巴」分支——尾巴分支只做两件事：去回声、补标点，然后把结果接在草稿后面。标记本身没有任何一处会被丢弃。

修复没有放宽到「任何 `XXX:` 都当标记」，而是对首行的大写词做编辑距离：`REWRITE` 容差 2 个字符，`SKIP`/`NOOP` 容差 1 个。代价是理论上有极小概率把「`REWRIT:` 开头的正文」当标记——但正文以全大写词加冒号开头的场景，在中文草稿里基本不存在，而把整句改写当成尾巴粘上去是每次都会发生的显性错误。

## 验证

那条真实回复的解析结果：

```
改前  {"mode":"append","tail":"RERITE:\n但是我还是想先确认一下这个方案。"}
改后  {"mode":"full","text":"但是我还是想先确认一下这个方案。"}
```

- 新增一条单测，覆盖：拼错（`RERITE:`）、少一个字母（`REWRIT:`）、只有标记（`REWRITE:` 单独一行 → 无建议）、反例（`CPU: 占用有点高` 仍是尾巴）。单测 193 → **194**。
- 变异反证：把距离阈值从 2 改成 0，这条检查立刻变红（`193 passed, 1 failed`）。
- 浏览器场景 **75/75** 不变。

## 升级

只改了宿主侧解析（`index.js`），浏览器端没有任何变化。**重启桌面应用**即可生效；`Ctrl+R` 不够。

如果哪天又看到标记漏进输入框，把那条草稿和灰字截给我——判据可以继续收紧，也可以改成「首行是 A–Z 全大写词加冒号就一律当标记」，只是那样会牺牲一点正文容错。
