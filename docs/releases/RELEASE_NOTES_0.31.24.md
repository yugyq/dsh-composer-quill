# 0.31.24

三处「用户能直接感觉到」的问题。

## 失败从来不说

模型调用失败时，插件把原因写进了内部状态，但**界面上没有任何一处读它**。你看到的现象是「补写中…」闪一下，然后什么也没有——既不知道失败了，也没有重试入口。

现在同一行会显示：

```
建议失败：model call failed
```

超过 60 字截断，完整原因在 `title` 里悬停可见；同时作为 `role="status"` 的内容播报一次。

## 脏候选会让整行建议消失

两条路径对新建议的校验不一致：SSE 路径要求每条候选都是非空字符串，JSON 路径只检查「是不是数组」。宿主回一条格式不对的数据，渲染期就会抛错，整行建议跟着消失。

现在两条路径共用同一个 `usableItems()`。

## `npm test -- --list` 少算 5 条

`--list` 的提前退出写在安全组之前，列出来 67 条、实际跑 81 条。现在早退在全部用例之后。

## 顺带修掉一个假绿的测试

S6「失败后自动重试恢复」一直在用 `setComposeMode('fail-always')` —— 而假模型从来没有实现这个模式，所以它一直悄悄走成功路径，测了个寂寞。补上 `fail-always` 之后，S6 才真正验证「失败一次 → 自动重试 → 恢复」，结论是重试确实有效。

## 测试

单测 81 → 83（`usableItems` 两条），浏览器场景 34 → 35（新增 S31：失败提示必须出现且带原因）。
