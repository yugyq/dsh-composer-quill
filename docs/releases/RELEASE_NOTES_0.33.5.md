# 0.33.5 — 灰字只画在该画的地方

npm 上从 0.33.3 直接跳到这个版本：中间的 0.33.4 只存在于仓库，从没发布过，所以这份说明覆盖 0.33.3 之后的全部改动——两批行为修正，加一条诊断通道。

起因是两条真机反馈：空输入框里冒出上一句话的灰字；切会话之后，本该出现的建议一直不出现。

## 五处行为变化

| 变化 | 改之前 | 改之后 |
| --- | --- | --- |
| 空输入框 | 会画出属于上一句话的整段建议 | 编辑器去空白后为空时，只画「下一句」这一种建议 |
| 找哪块输入框 | 取离 chip 最近的一块（120 像素阈值） | 结构判定：chip 所在的 composer → 祖先链里「子树恰好一块 composer」的那层 → 否则不画 |
| `claim()` | 每次调用都算换主人 | 幂等；重复认领返回「没有换主人」 |
| 输入框被宿主替换 | 图层随节点一起消失，建议没了 | 绑定到具体节点，替换后重新认领，建议继续在（S63） |
| 诊断上报 | 失败无痕；重载后可能整条通道哑掉 | 计数 `sent`/`failed` 搭 `/predict` 上报；keepalive 失败时用同一 body 重发一次 |

## 0.33.4：空输入框里没有「续写」可言

判断 compose 建议该不该画的三个条件里，没有一条问过「编辑器里还有字吗」。`followRemainder(full, '')` 在草稿为空时返回整个建议，`fresh` 又可能为真，于是属于上一句话的整段建议被当作「改写」画进了空输入框。

现在这段判断抽成 `composeVisible()`：store 必须属于当前会话、建议非空、**编辑器文本去空白后不能为空**，任何一条不成立都不画。日志对得上：`06:01:30.473` 的 `anchor:"caret"`、`draftChars:2`、`proposalChars:17`，长度与那句灰字吻合。

## 0.33.5：从结构上认领自己的输入框

原来 `composerForDock()` 按「谁离 chip 最近（120 像素以内）」挑输入框。这个阈值在任何一次布局变化、面板换行、侧栏展开之后都可能指错，而指错的结果不是不画，是画到别人的输入框里。像素现在不参与判断，`DOCK_REACH_PX` 已删除。

`claim()` 改成幂等：同一块图层重复认领返回「没有换主人」，StrictMode 下 effect 跑两遍不会看起来像被抢占。

宿主重建面板时会换掉输入框节点，图层跟着一起消失——新增场景 S63 覆盖：出建议 → 替换节点 → 建议必须还在、屏幕上只有一块图层。

试过用 `MutationObserver` 监听整棵树来重绑定，写完发现**去掉它场景照样绿**（别处已经在重画），按「不留没有失败用例钉着的代码」删掉了。这条如实记在这里，免得下次又有人想加一遍。

## 诊断通道：报告丢了要能自己说出来

同一天 75 次重载里有 5 次出现「模块报了到、之后再无任何上报」，而同一段时间里 `/history`、`/predict` 都正常——插件是活的，死的只有 `report()`，而它按设计失败无痕。

现在页面自己数 `sent`（发出次数）与 `failed`（非 2xx 或抛错），搭在每次 `/predict` 的 body 上，宿主写进 `request` 行；第一次尝试失败时，用同一个 body 再发一次普通请求——keepalive 请求在文档被替换时会被整批丢弃。

真机强制失败验证过：把第一次尝试改成必定失败后，`failed === sent`（31/31），而 `dock-state` 21 条、`paint` 8 条仍然全部到达，说明重发那条路是通的。

## 为什么以前的测试是绿的

空草稿这条规则从来没被单独断言过：三个条件里缺的那一条，只有在「建议还在、草稿刚被清空」的那一帧才看得见。图层归属更彻底——单测只跑纯函数，图层与 DOM 的归属没有断言；场景里的假宿主同一时刻只有一个 dock，而真实应用会留下被替换掉的那个。

## 验证

- 单测 **193**：`composeVisible` 十一种输入、`ownsCompose` 五个分支、`report()` 的重发（删掉重发那行即红）。
- 浏览器场景 **75**（S59 空草稿不画、S60–S62 图层归属、S63 节点替换后仍画）。
- 变异反证：删掉 `composeVisible` 的空串判断、把 `composerForDock` 退回「取第一个」、去掉 `claim()` 的图层次序、去掉 `report()` 的重发——各自只打红对应用例。
- `tsc -p tsconfig.json` 0 错误，`check:client` 一致。

## 升级

客户端改动 `Ctrl+R` 即可生效。`index.js` 只是多记一个 `request.beacons` 字段（诊断用），要重启桌面应用才会写进日志；不重启不影响任何建议行为。
