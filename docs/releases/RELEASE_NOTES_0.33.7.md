# 0.33.7 — 长建议不再被输入框剪断

上一版我试过「向宿主借高度」：撑高编辑器，再撑开夹住它的滚动容器，让长建议整段显示。真机上它会把排版递推下去（调大 `max-height` → 重排 → 算出同样的缺口 → 再调大），表现为界面卡住甚至崩掉。0.33.6 之后我把它撤了，退回「两行加省略号」。

这一版换了方向，也找到了真正的原因。

## 灰字这一层，一直挂在输入框里

`client/ghost-layer.js` 的 `mount()` 注释写着 "lives on `<body>` as a fixed layer"，代码是：

```js
host.style.cssText = 'position:absolute;left:0;top:0;width:100%;height:100%;…'
;(parent ?? document.body).appendChild(host)
```

`parent` 是编辑器的父节点。于是**父容器的 `overflow` 决定了灰字能有多高**：`fitToHeight` 想要多少高度都没用，超过两行就被祖先剪掉。这也解释了上一版为什么在夹具里能过、真机上不行——夹具的祖先有 `max-height` 夹住编辑器，真实应用里编辑器会真的变高，然后被外层的卡片剪断。

| 场景 | 0.33.6 | 0.33.7 |
| --- | --- | --- |
| 灰字挂载点 | 编辑器父节点（`position:absolute`） | `<body>`（`position:fixed`，`z-index:2147483000`） |
| 高度预算 | 可见框 + 两行，靠借宿主高度 | 视口的 60%，且不越过底部 12px |
| 超过预算 | 省略号截断 | 只在真的画不下时截断 |
| 宿主样式 | 会被改（`min-height` / `max-height`） | 一个都不碰 |
| 长建议 | 两行 | 整段，画在输入框下方 |

代价说清楚：很长的建议会画到输入框**下方、盖住页面内容**（半透明灰字，仍可读）。滚动与窗口缩放都会跟着重排；Esc 关闭、Tab 采纳的行为不变，Tab 插入的仍是完整建议。选择这条路，是因为另一条路要动宿主的卡片布局——风险高一档，收益只是不遮挡。

## 两条场景改了口径

- **S64** 从「必须裁成两行」改回「整段画出、没有省略号、图层挂在 `BODY`、页面仍响应」。夹具的 402 字建议实测：`字数=402 截断=False 灰字高=176 宿主=BODY`。
- **S26** 原本钉「灰字不越过输入框的滚动框」——那正是被剪的原因。现在改成「不跑出视口」，并临时把视口压到 220px 高，让预算真的夹住 176px 的灰字：`视口=220 灰字底=194 ≤ 214`。

变异各自打红对应的一条：

| 变异 | 结果 |
| --- | --- |
| 图层放回输入框内 | S64 红（`hostParent=DIV`） |
| 预算钉成 48px | S64 红（只画 98 字，带省略号） |
| 去掉上限（返回 5000） | S26 红（灰字底 260 > 视口 220） |
