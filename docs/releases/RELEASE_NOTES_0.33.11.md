# 0.33.11 — 输入框自己长高，灰字留在里面

上一版给长建议垫了一块白底面板，好让它不直接压在页面文字上。方向错了：建议是你正在写的那句话，它应该让输入框变高，而不是在页面上多盖一张卡片。

这一版把面板整块删掉，改成抬高宿主编辑器的 `min-height`：灰字要多少高度，输入框就长多少，末行落在卡片自己的圆角边框里。

## 行为变化

| 之前（0.33.10） | 现在（0.33.11） |
| --- | --- |
| 长建议从第二行起铺一块 97% 白的圆角面板 | 面板不存在了；输入框长高，灰字在卡片内 |
| 卡片高度 48px，灰字溢出到卡片外 80px | 卡片高度 = 灰字高度（402 字实测 176px） |
| 撑高逻辑曾因无出口递推把主线程占满（0.33.6） | 三条闸：真差 2px 以上才抬、同高度只抬一次、抬不动就永远收手 |

## 怎么保证它不会再崩

`client/ghost-layer.js` 的 `growEditor(wanted)` 只改 `min-height`，并且：

1. **只差 2px 以上才抬**，抬到刚好够就停——否则「刚撑到刚好」的下一帧会被判成不需要撑，卡片会在 176 → 48 → 176 之间抖（夹具时间轴上真的出现过）；
2. **同一高度只抬一次**；抬一次没长（宿主把高度钉死）就把 `min-height` 还回去，并置 `growBlocked`，此后不再尝试；
3. **文本变短或清空时还原**：`clear()` 里恢复挂载时记下的原值。

截断判据也跟着换了：撑高成功就按视口预算排版（不再有「两行」上限），只有宿主拒绝长高时才退回按可见框截断。

## 验证

- 单测 **197**（不变）。
- 浏览器场景 **76/76**：S64 改成「卡片高度 ≥ 灰字高度、灰字底边与卡片底边的差 ≥ −2px、页面里不存在底板元素」。
- `tsc` 0 错误，`check:client` 与源文件一致。
- 真机（桌面应用，`Ctrl+R` 后同一段 86 字草稿）：卡片长到三行，灰字末行在卡片内，页面里没有底板元素。

## 升级

只改了客户端：`Ctrl+R` 即可。宿主 `index.js` 未变。
