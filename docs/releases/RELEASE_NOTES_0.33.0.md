# 0.33.0 — 截图里的那串数字，现在是它自己读到的

以前在输入框里贴一张截图，问「这个截图里的数字是」，补全不会说「我看不到」——它会顺着上下文编一句读起来很顺的话。这一版把图片和文件接进了建议链路：**模型看见的是附件本身，不是一句"这里有张图"的说明**。

## 三条行为变化

| 变化 | 改之前 | 改之后 |
| --- | --- | --- |
| 图片 | 模型只收到草稿文字，图片从未离开浏览器 | 宿主把图片作为 `ImageBlock` 放进消息，草稿仍排最后 |
| 文件 | 完全不可见 | ≤ 8 KB 整份贴上；更大只给前三行，并明说其余未知 |
| 新建会话 + 图 | 「下一句」直接返回空（`empty-thread`），输入框毫无反应 | 空框里有图就照常问一次，图随消息进上下文 |

## 怎么走的

浏览器上传完图片/文件后，插件手里只有 `input.attachmentIds`。现在它把这些 id 换成四个字段——`kind`、`name`、`bytes`、宿主的上传回执 `receiptId`——随补写请求发给本机宿主。**字节不经过插件的任何路由**，48 KB 的请求体上限没动，也不需要把 base64 塞进请求体。

宿主拿到回执之后：

- **图片**：`fileUploads.resolve(agent, receipt)` → `ImageAttachmentRef` → `ImageBlock`。`deepseek-flash` 声明的输入模态含 `image`，所以默认建议模型真的看见了；纯文本模型由 `dsh-llm` 自己换成 `[image omitted because this model accepts text only; …]` 占位符，插件不用另写分支。
- **文件**：宿主用 `fileHostPath()` 读，按大小分两档——8 KB 以内整份交出（`Its text, in full:`，不加 hedge）；更大的只给前三行（`Only its first 3 lines are shown here`，并明说其余未知、不要猜、去问用户）。二进制或读不到时只给名字与大小。
- **回执过期或对不上**：不假装看得见，提示词里写明「宿主还没收到这个附件，看不到就不要描述或引用」。

## 量出来的数字

图片的 token（`deepseek-flash`，thinking disabled，同一条纯文本基线 9）：

| 输入 | input tokens |
| --- | --- |
| 520×180 截图 | 196 |
| 1440×900 截图 | 804 |
| 2880×1800 截图 | 972（接口自己缩放，不随像素线性涨） |
| 8 × 1440×900 | 5601 |
| 8 × 520×180 | 1377 |

延迟代价是真的：同一条草稿 611 ms（纯文本）→ 982 ms（带一张 1440×900）。前缀缓存不受影响——长 system 下同一张图第二次、第三次都是 `cache_read: 1664`，那 ~187 token 进了缓存；换一张图就是换前缀，必然全价。输出预算不被图片占用：8 张图 + `max_tokens: 64` 仍然输出完整句子。

## 文件读不全时，它会去要

这是这一版最实的收益。同一批草稿、真模型、每次四条：

| 文件档位 | 「第一条报错是什么」 | 「最后那个仓编号是什么」 |
| --- | --- | --- |
| 只给名字+大小 | 0/4 答不出（全在要文件） | 4/4 不编 |
| 只给前三行 | **4/4 答对** | 4/4 不编（问用户） |

而"截断但不说"是最危险的：长文本只给前 1600 字、不提示，**4/4 都在编**（`WH-02`、`SH-01` 这类像真的仓编号）；只在说明里加强措辞还能编 2/4；说明写清「后面你并不知道，不要猜，去问用户」+ 规则里重申，**5/5 全部改成去要文件**。二进制文件从「4 次编 1 次」变成 0/5。

## 附件和打字等权

请求的身份从「草稿」变成「草稿 + 附件指纹」：加一张图、换一张图、撤掉一张图，都和敲一个字一样触发同一套去重、取消、防抖与重问。在飞的那条答复是在没有这张图时写的，所以会被丢弃而不是留在屏幕上。存下来的旧建议只在没有附件时复用——它没有附件语境。输入框空着时同理：空框里多一张截图，「下一句会说什么」的候选换答案，`next` 请求现在也带着附件。

## 一个只有真机才会暴露的 bug

第一版客户端里，`conversationOf()` 直接读 `ctx.conversation`，而插件的 `inject` 只有 `['slots','locale']`。客户端运行时的 guard 对**未声明的直接属性访问**是拒绝并抛异常的，异常被 `try` 吞掉 → 附件列表恒空。单测全绿，真实请求里 `attachments` 一条都没有。修法是显式声明 `'conversation'`，并让直接读被拒时回退到 `ctx.get('conversation')`；新增用例用会抛异常的桩把这个回退钉住。

## 验证

- 单测 168 → **178**，浏览器场景仍是 **66**。
- 每一处都反证过：指纹恒空、不 push 图片块、回执恒空、客户端传空数组、门禁键去掉附件、签名忽略附件、触发规则恒假、`next` 不带附件、宿主对 `next` 丢掉附件、空会话闸门两个方向——对应用例各自变红。
- 真模型探针（`dev/probes/probe-attachments-live.mjs`，要花真钱，不进 CI）：图片里的数字只有带着图片才说得对；文件里的仓编号只有带着文件才说得对；读不出正文的文件不会被编内容；空会话带图能出第一句、不带附件时一次模型都不调。

## 兼容与升级

- 建议模型的输入模态决定图片能不能真的被看见：`deepseek-flash` 可以；纯文本模型会收到占位符，仍不会编。
- 请求体新增可选的 `attachments`（≤ 8 条，`kind`/`name` ≤ 120 字符、`bytes`、`receiptId` ≤ 200 字符），参与缓存键；`docs/PROTOCOL.md` 已更新。
- `SECURITY.md` 加了 Attachments 一节：字节不经插件、宿主解码、文件最多读 96 KB、超过 8 KB 只发前三行。
- 宿主代码（`index.js`）变了，**升级后要重启桌面应用**；只改客户端时 `Ctrl+R` 就够。
