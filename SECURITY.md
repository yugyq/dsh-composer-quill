# Security

## What this plugin can reach

`dsh-composer-quill` runs inside DeepSeek Harness, in the Host process and in the Web UI. That gives it access to two things worth naming:

- **Session events.** The plugin reads the current Session's messages to build a prompt. It uses the last two turns plus one older row related to your draft. It does not read other Sessions, workspaces, or files.
- **Your configured model route.** Suggestions are generated by calling the model you already configured in DSH, with your credentials, through the Host. The plugin never reads, stores, or forwards those credentials.

## What leaves the machine

Only the prompt sent to your model provider, and only what that prompt contains: your draft, the last turns of the conversation, a short digest, a style summary, and the latest assistant reply.

Before the prompt is sent, nine shapes are replaced with `[redacted …]`: PEM private keys, AWS `AKIA…`, GitHub `ghp_` / `github_pat_`, OpenAI `sk-…`, Stripe `sk_live_`, Slack `xox…`, JWTs, `Bearer …` tokens, and long base64 secrets.

Your draft is redacted on the same rules. A rewrite that comes back carrying a `[redacted]` marker is discarded rather than offered, so a draft holding a secret produces no suggestion instead of leaking one.

There is no telemetry, no analytics endpoint, no update check, and no third-party server. The only network calls are the ones made by DSH itself to your model provider.

## Local files

All three live in one state directory: `$DSH_PROFILE_DIR` when a profile is set, else `$DSH_HOME`, else `~/.dsh`. `DSH_COMPOSER_QUILL_STATE_DIR` pins it for tests and diagnostics. The bare home directory is never used.

| File | Contents |
| --- | --- |
| `<state>/composer-quill.log` | JSONL diagnostics: request shapes, cache hits, result counts, timings. Prompts and drafts are not written here; the digest and style summary are not either. |
| `<state>/composer-quill-usage.json` | Call counts, token counts, and a cost figure in micro-USD. Numbers only. |
| `<state>/composer-quill-cache.json` | The suggestions themselves, in plain text, so a restart does not re-pay for a suggestion you already saw. Cleared on request. |

Browser settings live in `localStorage` under `dsh.composer-quill.*`.

## HTTP routes

Five routes are registered on the DSH web server. All of them require either this launch cycle's token or a same-origin browser request; `/composer-quill/history` and `/composer-quill/models` accept the token only.

| Route | Purpose |
| --- | --- |
| `POST /composer-quill/predict` | Suggestions |
| `POST /composer-quill/history` | Your own past messages, for history completion |
| `POST /composer-quill/beacon` | Diagnostics from the UI |
| `POST /composer-quill/usage` | Read or reset the usage ledger |
| `POST /composer-quill/models` | The provider and model list for the settings page |

## Reporting

Open a [private security advisory](https://github.com/yugyq/dsh-composer-quill/security/advisories/new) rather than a public issue. Include the version (`dsh-composer-quill` version and DSH version), what you expected, and what happened. If the report involves a log line, paste that line; logs contain no prompts or credentials.

Expect an acknowledgement within a few days. This is a single-maintainer project, so please allow time for a fix; there is no bug bounty.
