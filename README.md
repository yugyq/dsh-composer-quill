# 续笔 · dsh-composer-quill

DSH 输入框的补全插件。[English](README.en.md)

> 如果对你有帮助，点个 [Star](https://github.com/yugyq/dsh-composer-quill)。

回合结束时给几条「下一句」，你打字停一下就把后半句接上。`Tab` 采用，`Esc` 忽略；发送还是你自己按。

![下一句：输入框为空时给出候选，提示条上标着第几条](docs/assets/real-next.png)

```bash
dsh plugin --profile desktop add dsh-composer-quill
```

- **不知道怎么开口**：回合结束先摆几条下一句，挑一条改比对着空白想快
- **句子组不顺**：写个开头，后半句接上；整句都乱，它给一整段整理过的
- **说到一半被打断**：切走再回来，建议还在原位
- **每次都要重打的那段话**：从你自己的历史里取，不花模型调用

完全在本机：请求走你已经配好的模型路由，没有第三方服务器，也不上报任何东西。

## 四种建议

三种要花模型调用，多数情况一次：补写在主答案解析不出结果时会再要一次，下一句只给出一条时也会补问一次。历史不花。

**下一句**：回合刚结束时给几条，`←` `→` 换。切回一个聊过的会话时也会给。

**补写**：打字停一下就出；你继续打字，它一点点收窄，最后只剩尾巴那几字。

![补写：深色是已输入的内容，浅色是接上的后半句](docs/assets/real-tail.png)

**改写**：错字、标点乱、一句话塞了好几件事，它给一整段整理过的；采用就是整段替换。

![改写：草稿里的错字和断句被整理成完整的一句，提示条上是改写后的版本](docs/assets/real-rewrite.png)

**历史**：以前说过类似的话，它直接从你的历史输入里取，不花模型调用，毫秒级。

![历史：打到一半时，后面接上你以前说过的原话](docs/assets/real-history.png)

这三件事都不会打断你：

- `Esc` 关掉之后，同一份草稿不会再弹回来
- 请求进行中不清空重来，上一条建议留在屏幕上，标一个「· 补写中…」
- 组字期间不打断输入，也不把组字内容当成草稿

## 按键

| 按键 | 作用 |
|---|---|
| `Tab` | 采用当前建议 |
| `←` `→` | 换候选，只有「下一句」有多条时 |
| `Esc` | 关掉建议；同一份草稿不会再弹回来 |
| `Ctrl+Shift+Space` | 手动要一条，「仅手动」模式下是唯一入口 |

建议显示时 `Tab` 被采纳占用。要换焦点，先按 `Esc` 关掉建议，`Tab` 就交还宿主；回车不受影响。

## 安装

需要 DSH `>=0.2.1-rc.2 <0.3.0`（不匹配的宿主会在安装阶段被拦下），并且已经在 DSH 里配好一个可用的模型。插件不改装模型，只借用你现有的路由；没配模型时不会有任何建议。

```bash
dsh plugin --profile desktop add dsh-composer-quill                # 从 npm 装
dsh plugin --profile desktop add github:yugyq/dsh-composer-quill   # 或从仓库装
```

界面里也行：**设置 → 插件 → 添加插件**，填 `dsh-composer-quill`。

从源码接入、判断在跑哪一版、改完代码怎么生效——见[开发与验证](docs/DEVELOPMENT.md)。这是第三方插件，与 DeepSeek 官方没有隶属关系；遇到问题请开 [issue](https://github.com/yugyq/dsh-composer-quill/issues)，附上日志里相关的那几行。

## 设置

**设置 → 续笔**：设置导航里独立的一节，不挤在「通用」里。

| 项 | 默认 | 说明 |
|---|---|---|
| 下一句 | 开 | 空输入框时给候选下一句 |
| 补写 | 开 | 打字时补全，并顺手整理草稿 |
| 模式 | 自动 | 「仅手动」时只在按 `Ctrl+Shift+Space` 时请求 |
| 语言 | 跟随系统 | 指定后强制；草稿语言不同会整段翻译 |
| 停顿 | 120 ms | 打字停多久发请求，范围 80–2000 |
| 超时 | 20000 ms | 单次请求上限，范围 3000–60000 |
| 模型 | 跟随会话 | 建议用哪个模型；列表来自 DSH 已配置的路由，选了不影响会话本身 |
| 思考 | 关闭 | 建议用多深的思考；调高更慢更贵，复杂改写可能更准 |

「下一句」和「补写」是两个独立开关，只想要一个就关掉另一个。

**消耗**：面板显示今天与累计的调用次数、输入/输出 token、折算成人民币的金额，可一键重置累计。金额按**调用发生时刻**的峰谷价结算（峰时是 UTC 工作日 01:00–04:00 与 06:00–10:00），账本在 `~/.dsh/composer-quill-usage.json`，只有数字。

**采纳反馈**：`Tab` 采纳、`Esc` 忽略、没采纳就发送都计入，用来重排「下一句」候选。

配置存在浏览器的 `localStorage` 里，不联网。

## 隐私

- **只在本机**：补全请求走 DSH 已配置的模型路由，没有第三方服务器，也不上报。
- **遮蔽凭据**：上下文出机器前，九类形状会被换成 `[redacted …]`——私钥块、AWS `AKIA…`、GitHub `ghp_` / `github_pat_`、OpenAI `sk-…`、Stripe、Slack `xox…`、JWT、`Bearer …`。
- **草稿同样遮蔽**：草稿里若出现密钥形状，也会换成 `[redacted …]`；解析层会丢弃带遮蔽标记的改写，所以宁可这次不给建议，也不把密钥发出去。
- **三个本地文件**：诊断日志 `~/.dsh/composer-quill.log`、用量账本 `~/.dsh/composer-quill-usage.json`（只有计数与金额）、建议缓存 `~/.dsh/composer-quill-cache.json`（存建议正文，删掉即清空）。三者都在同一个目录，跟着 `DSH_PROFILE_DIR` / `DSH_HOME` 走。
- **接口有鉴权**：宿主侧要求本启动周期的令牌或同源浏览器请求；会话历史接口只认令牌。

## 它怎么工作

- **流式**：补写走 SSE，模型边写边长，`Tab` 随时可采。
- **两种回答**：接在草稿后面的尾巴，或 `REWRITE:` 加一整句。
- **上下文**：只看最后两轮，更早的对话只作背景，且只留一条与草稿相关的旧行。
- **缓存键**：绑定「草稿 + 对话版本 + 设置」，键不变就回放，键一变就作废，同一份草稿不会重复花钱。
- **五条本地路由**：`/predict` 出建议，`/history` 取你的历史消息，`/beacon` 收诊断字段，`/usage` 读写用量账本，`/models` 给设置页列出可选模型。全部只接受 `POST`。
- **排版**：建议层嵌在输入框内部，换行和裁切都交给宿主。

细节见 [架构设计](docs/ARCHITECTURE.md) 与 [接口与流式协议](docs/PROTOCOL.md)。

## 测试

单测 149 项、浏览器场景 64 项，跑在 CI 里。场景覆盖快速连打、停顿出建议、取消、切会话、长文本排版这些真实节奏。

```bash
npm test                          # 148 项离线单测
npm run test:ui                   # 64 条浏览器场景（自带模拟器）
npm test -- --filter=transcript   # 只跑某个行为
npm test -- --list                # 列出全部用例名
```

真机脚本、审计探针和模拟器都在 `dev/`，用法见 [开发与验证](docs/DEVELOPMENT.md)。

## 还没做好的地方

- **宿主还没加载会话时**：拿不到上下文，「下一句」和历史补全没有内容可依；补写仍可用。
- **一两个字的草稿**：基本靠猜，给的多是完整短句。
- **长度上限**：建议最多换到三行，再长就省略，因为输入框本身也只长到那里。

## 诊断

出问题先看 `~/.dsh/composer-quill.log`，每行一条 JSONL。

- `request` / `cache-hit` / `cache-miss`：有没有真的调用模型；miss 会记下键的各个成分。
- `result`：返回了几条候选；失败原因是 `skipped` / `empty-thread` / `wrong-language`。
- `empty-reply`：模型一个字都没返回，带当时的输出上限与 `finish` 原因。
- `model-override` / `reasoning-setting`：设置里选的模型与思考档位确实生效了。
- `hydrated`：复用了存储里的建议。
- `next-ungrounded` / `next-empty`：候选与会话无关 / 一条都没剩下。
- `dock-state`：界面那一刻的完整状态——阶段、候选数、草稿是否为空。
